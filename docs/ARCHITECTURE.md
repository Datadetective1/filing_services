# Filewell architecture

Filewell is a private, self-service filing-assistance service for U.S. business
compliance filings, starting with annual reports. It is **not a government agency**
and must never look like one.

Operating model: **manual fulfillment → assisted → automated → exception-only**.
Today every filing is fulfilled by a human operator from a generated filing packet.
Automation replaces individual steps later without changing the data model.

## Stack

- Next.js 16 (App Router, React 19, Server Components, Server Actions). `proxy.ts`
  replaces middleware. `params`, `searchParams` and `cookies()` are async. Typed route
  helpers `PageProps<"/path">`, `LayoutProps<"/path">`, `RouteContext<"/path">` are
  generated by `npx next typegen`.
- Tailwind CSS 4 with semantic tokens in `src/app/globals.css`.
- Supabase: Postgres (+ row-level security), Auth (email + password, email
  verification, password reset), Storage (private bucket `filing-documents`).
- Zod 4 for validation. Vitest (unit + database), Playwright (end-to-end).
- Payments behind `PaymentProvider` (sandbox simulator or Stripe hosted Checkout).
- Email behind `EmailProvider` (outbox or Resend).

## Security model

1. **RLS on every table.** Customers can read only their own rows. Staff read via
   `is_staff()`. Money, status and compliance tables (orders, payments, refunds,
   filings, requirements, documents, receipts, reminders, notifications, audit) are
   **never writable by end users**; the server writes them with the service role
   after authorizing the actor.
2. **Staff roles live in `staff_members`**, checked per request (`requireStaff`,
   `requireAdmin` in `src/lib/auth/session.ts`). Never a client flag, never a JWT claim.
   Every admin page AND every admin server action calls `requireStaff()`/`requireAdmin()`.
3. **Status changes only through `transition_filing()`** (SQL, SECURITY DEFINER,
   service_role only). A trigger rejects direct status updates. Each transition writes
   `filing_status_history` + `audit_logs` in the same transaction.
4. **Audit log is append-only** (trigger). `src/lib/audit.ts` throws if the write fails.
5. **Webhooks**: raw body signature + timestamp verified; events deduplicated by
   `(provider, provider_event_id)`; payment SQL functions never move a payment backwards,
   so duplicate and out-of-order deliveries are harmless.
6. **Documents**: private bucket, no client storage policies. Download = RLS-checked read
   of the document row as the user, then a 60-second signed URL (`/api/documents/[id]`).
7. **Secrets** only in environment variables (`src/lib/env.ts`); never logged, never in
   `NEXT_PUBLIC_*` except the Supabase URL and publishable key.
8. **Safe-by-construction adapters**: under the test runner the sandbox payment provider
   and the outbox email provider are always used. The Stripe adapter refuses live keys
   unless `PAYMENTS_LIVE_ENABLED=true`. Live checkout refuses unapproved service prices.

## Compliance data

- `src/lib/compliance/registry.ts` is the source of truth for rules. Each rule version
  is seeded into `state_rule_versions` (immutable once published, content-hashed) with
  its `state_rule_sources` (official URL, verbatim quote, last verified date).
- A filing stores `rule_version_id` + `rule_snapshot` at creation; an ordered filing's
  rule is frozen (trigger). Law changes = new version; old orders are untouched.
- Only `verified` rules may be presented as facts or sold. Every other state is
  UNVERIFIED: pages are `noindex`, show only the official agency link, and make no claims.
- Research + two-reviewer verification log: `docs/research/`.

## Money

Integer cents. `orders.government_fee_cents` and `orders.service_fee_cents` are always
separate (`total_cents` is a checked sum). Refunds record the government and service
portions separately. Service fees are admin-configurable (`service_prices`); the seeded
PA fee is **provisional and unapproved**.

## Filing lifecycle

```
draft ─pay─▶ ready_for_review ─▶ ready_to_file ─▶ in_progress ─▶ submitted ─▶ accepted ─▶ completed
   │  (needs_information if intake incomplete)        │                 └▶ rejected ─▶ ready_to_file / needs_customer_action
   └▶ cancelled ─▶ refunded        needs_customer_action ◀── operator requests info
```
The canonical map is `src/lib/domain/filing-status.ts` (mirrors SQL).

## Reminders

`filing_requirements` = one row per business × rule × period. Reminders are planned per
requirement (default offsets −90…+30 days) and evaluated **at send time** by
`reminderDecision()`: cancelled when filed/cancelled/not required, skipped when opted out
or stale, "needs information" variant while waiting on the customer, silent while we are
handling it. A daily cron (`/api/cron/reminders`) runs `runReminderCycle()`. Accepting a
filing closes its reminders and opens next year's requirement.

## UI conventions

- Direction: warm, calm, human, photography-led; an American small-business service, not
  enterprise SaaS. Light only (no automatic dark mode). The admin console uses dark `ink`
  surfaces for its sidebar.
- Tokens (`src/app/globals.css`): `bg-bg` page, `bg-surface` cards, `bg-surface-2` stone
  bands, `border-border`, `text-fg` / `text-muted` / `text-subtle`. Pine is the action and
  brand color (`bg-accent text-accent-fg`, `bg-accent-soft`). Marigold is the single
  highlight accent (`bg-highlight`, `bg-highlight-soft`, `.mark-highlight`) and is never
  used for body text. Semantic `warning` / `danger` / `info` (+ `-soft`).
- Shape: buttons are pills; controls `rounded-[var(--radius-control)]` (10px); cards and
  panels `rounded-[var(--radius-surface)]` (18px); photos `rounded-[var(--radius-photo)]` (22px).
- Typography: Bricolage Grotesque for every h1-h3 (and `font-display`), Figtree for body,
  Geist Mono for confirmation numbers. Money/dates use class `tnum`.
- Photography: licensed Unsplash images stored in `src/assets/photos/` (credits in
  `CREDITS.md` there and on `/credits`), registered with alt text and crop focus points in
  `src/lib/media/photos.ts`, rendered with `<Photo>` (`src/components/media/photo.tsx`).
  Never caption them as customers.
- Visual objects (`src/components/visual/`): `CountdownRing`, `ReminderTimeline`,
  `Receipt`, `DocumentSheet`/`DocumentTile`, and the `/states` tile map. Money is shown as
  a receipt, documents as paper, deadlines as countdowns, progress as step trackers.
- Icons: Phosphor only. Server components import from `@phosphor-icons/react/dist/ssr`,
  client components from `@phosphor-icons/react`.
- Primitives: `Button`/`ButtonLink`/`buttonClasses`, `Field`/`Input`/`Select`/`Textarea`/
  `Checkbox`, `SubmitButton` (pending state), `Badge`/`FilingStatusBadge`/
  `PaymentStatusBadge`, `Card`, `Container`, `PageHeader`, `Notice`, `Facts`, `EmptyState`,
  `SectionTitle`, table primitives (`TableScroll`, `Table`, `THead`, `TH`, `TR`, `TD`).
- Copy: plain and factual. Separate FACT ("Based on the Department of State's published
  requirements…") from SERVICE OFFER. No legal advice. No fake testimonials, logos,
  counts or manufactured urgency (a countdown only ever shows a real, verified due date).
  No em dashes in visible copy. Every page that sells shows
  the disclaimer and the option to file directly with the state.
